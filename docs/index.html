Markdown workspace
for humans and AI agents.

An AI agent that works in your folder of notes, plans, and task boards. It browses, plans, and proposes real changes, then waits for you to approve the diff before it writes anything. And one Markdown file can be a board, a list, a table, a calendar, or a chart.

Layouts

One Markdown file, many layouts.

A board, a list, a table, a calendar, a timeline, a gallery, or a chart is not a different file. It is one layout: line in the frontmatter. Change that line, or pick a layout from the header bar, and the same notes appear in a new shape. The text is never converted.

Every layout edits the same Markdown text, with one undo step per change. The agent can add notes, fill in fields, and switch the layout too (describe_schema, query_notes, edit_note, edit_schema), as a diff you approve first.

Collaboration

Review and merge pull requests next to your notes.

Open a clone of a Forgejo or Gitea repository and its open pull requests appear in the sidebar. Read a change as a note, comment on it, merge it, resolve a conflict on your own computer, or send your edits as a pull request. A new pull request raises a desktop notification.

Merging asks first (merge commit, squash, or rebase), and nothing is pushed before you press the button. The access token stays in the system keyring and reaches git only in the environment of a push. Forgejo and Gitea only for now; GitHub and GitLab are not supported yet. Read the documentation.

Agent features

The agent works, you decide

Ask for results, not only answers. The agent reads freely, writes only through proposals, and checks its own results.

How it works

One day of work, from Home to done.

Everything is a Markdown file in one work folder, so each step feeds the next.

1. Home

Start the day knowing what to continue.

Open Markwork and Home already shows where you left off.

  • Recent files, today's journal, and agents that are running or waiting for you
  • Due dates from every kanban board, and the inbox that still has unprocessed notes
  • Check a task right on Home and it is written back to its board

About Home →

2. Inbox

Capture first, sort later.

Ideas, links, and quick notes go into the inbox in one line.

  • Type in the top field and press Enter; the note is time-stamped and tagged with #tag
  • Process it later: turn the notes worth doing into kanban cards
  • It stays a plain Markdown list, with undo for every change

About the inbox →

3. Journal

The day writes itself.

You jot short notes; Markwork adds what already happened.

  • Quick capture with Ctrl+Shift+J without leaving the document you are in
  • Cards moved, agent changes applied, harness results, and Git commits are merged into the Activity section
  • At the end of the day the Assistant proposes a summary, and nothing is written before you apply it

About the journal →

4. Kanban

Plan the work on a board.

A kanban board is also just a Markdown file.

  • Drag cards between lists; due dates [due:: date] show up on Home
  • Tags, notes, and checkboxes on every card
  • Moves are recorded in the journal

About kanban →

5. Agent

Ask for results, you decide.

Ask in plain language; the agent reads your folder and proposes the work.

  • “Update the release date and move the release material card to In Progress.” Each change is a proposal with its diff
  • Apply or reject; every application can be undone, and Markdown files outside the folder are never touched
  • For several steps it plans, proposes one batch, and verifies the result. A card marked @pi goes to another agent in a project repo

Proposals and approval →

Orchestrator

Assign cards to another agent.

Write @pi on a kanban card, right-click, then Work on it with pi. The pi harness works in the project repo that you choose, and Markwork handles the rest.

  • The card moves to In Progress on start and to Review when done, with a summary of the result
  • Questions and permission requests from pi are answered from the card: Answer pi…, Steer, or Reply
  • One project is worked on by one harness; other cards queue
  • The pi log holds the tools, the reasoning, the tokens, the cost, and the session id
